## Verdict on the code
- **modal_p.py log-prob: correct.** The logits slice `[len(p)-1 : len(p)+len(c)]` gives len(c)+1 rows. Row k scores c[k], and the last row is the "next token is not a digit" term. Right padding plus the attention mask plus causal attention means real tokens never see the padding. Prompt is built as template text, then `add_special_tokens=False`, so there is no double BOS (OLMo-2's template already puts in its own BOS). This is the same prompt string the judge greedy run used. The candidate goes in as raw tokens right after the generation prompt. Qwen splits digits one per token, which is why the not-digit term matters, and the code has it. phi-4 and OLMo-2 (cl100k-style tokenizers) give a single token for numbers up to 999, and the prompt ends in `<|im_sep|>` / `\n`, so splitting the candidate on its own matches how it splits in context. The digit mask counts " 5" (space plus digit) as a digit. That is harmless.
- **make_p.py variants: match PLAN.md.** For every instruction-kind item, the correction sits on the first line and the question on the second (all 3 wordings checked), so NOINS keeps just the question. NOEX is head plus final, and NOINS for the other kinds is ex plus final, both as described.
- **score_p.py: log-odds, AUCs, bootstrap over (fact, seed), and the P1/P2/P3 rules all match the plan text.**

## REQUIRED (must fix before run)
1. **The "answer starts with the number" measure misses most truth answers.** In the judge main run, the truth-source answers that do NOT start with the number are 53 of 71 for qwen14, 70 of 93 for phi4 and 9 of 95 for olmo13 (for example "A hexagon has 6 sides."). The three candidates then share only a sliver of the probability. In smoke, qwen's total log P over the 3 candidates goes as low as -35. So log-odds, `lowconf` and the removal drops are comparing digit-start tails, not the forces. Minimum fix: save and report logsumexp of the 3 candidates per prompt, then report P1/P2 separately for rows where it is >= log 0.5 versus the rest. Better fix: also score the truth number inside a short sentence prefix, or put an "other" mass into the log-odds denominator. Pre-register which of these you choose.
2. **P2 lacks the trivial baseline, so it can pass or fail for the wrong reason.** In real use the answer is visible, so "answer = favourite" (`coarse`) is the obvious detector. The fine lamp is mostly that same signal through P1. From the main greedy data, qwen14's coarse lamp alone comes out around AUC 0.75 (72 of 76 errors are instruction answers, plus 99 correct instruction answers). In smoke, coarse beat fine for qwen and phi4. P2 should require the CI of (fine − coarse) > 0 as well as, or instead of, (fine − lowconf).
3. **P2 for phi4 has no power.** phi4 made 7 direct errors out of 300, all in the truth kind. An AUC on 7 positives clustered by fact cannot carry a PASS/FAIL rule. Either make phi4 descriptive only, or set a minimum error count (for example >= 20) below which P2 is reported as "not testable".
4. **P3 is close to automatic.** The removed number is usually the only place that number appears, so its log-odds falls to a floor that is about the same for every candidate. The drop is then roughly FULL log-odds minus a constant, so "bigger drop = followed force" is mostly P1 again. On smoke, the P3 decision equals the plain FULL comparison of examples vs instruction log-odds in 19/20 dialogues (phi4), 18/20 (olmo13) and 13/20 (qwen14). Also, in the instruction kind, NOEX still has the "examples" number X as the first-turn instruction, and NOINS turns X back into the live instruction, so the two removals are not symmetric there. Fix: P3 must beat the FULL-log-odds baseline (report both, and require agreement among the cases where they differ, or a margin), or redefine it as "which removal flips the argmax". Report P3 per kind.
