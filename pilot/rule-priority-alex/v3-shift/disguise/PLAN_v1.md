# План: «переодевание» задачи и «встряхивание» модели

Черновик 2026-10-18. До кода и прогона его смотрит независимый проверяющий. После правок пишу PREREG.md с контрольными суммами, и только потом Alex называет число.

## Вопрос

Привычка «из обучения» срабатывает на уверенности, без сомнения (general-lamp/rezultaty.md). Проверяем два внешних способа вернуть модель «в реальность». Устройство модели ни в одном не меняется.

1. **Переодевание (идея Claude).** Внешний модуль переписывает задачу нейтральными словами, чтобы привычке не за что было зацепиться. Модель решает и обычную, и переодетую версию. Если ответы разные, модуль берёт ответ переодетой.
2. **Встряхивание (идея Alex, как в Impulse Lab).** Перед вопросом модель получает неожиданность.

## Модель

Qwen2.5-14B-Instruct, обычный проход без вмешательств. Исключение — плечи «шум», где вмешательство и есть проверяемый способ.

## Задачи

**N-traps, «родные» дорожные слова, смена правила без истории.** native/make_native.py, плечо change_0, пробы D1–D4. 90 наборов: генератор запускается с числами S, S+1, S+2, использованные раньше пропускаются. Правильный ответ — по новому правилу. Привычный — по здравому смыслу (старое правило).

**N-same, контроль вреда.** Те же запросы без строки «IMPORTANT UPDATE». Правильный ответ — старое правило, то есть привычка здесь права.

**R-traps, redefine-math.** Проверочная часть из general-lamp: 810 вопросов, деление числом 12345. Правильный ответ — по переопределению.

**R-same, контроль вреда.** Те же вопросы, но всё до «Q:» убрано (переопределения нет). Правильный ответ — обычная математика. Это второй вариант ответа, ранее «привычный».

**Только для отчёта: C-rule.** match/make_match.py, A_change_60 × D1–D4, 90 наборов с теми же числами. Это привычка «списать из примеров», на ней проверяем только встряхивание.

## Как спрашиваем

**N и C** — в своём чат-формате, как раньше.

**R** — формат F2: чат, «Reply with only the answer, nothing else.», ответ начинается с «The answer is». F2 выбран заранее: у redefine на пробной части у него самая высокая медианная доля вероятности на вариантах (devformat_out.json: F2 1.00, F1 1.00, F3 0.39).

**Ответ модели** — вариант с наибольшей суммарной log-вероятностью. Варианты: для N и C — три метки набора, для R — два числа задачи.

**Фильтр:** в подсчёт идут только вопросы, где у обычной версии доля вероятности на вариантах ≥ 0.5. Вопрос либо входит во все способы сразу, либо ни в один.

## Способы (все сравниваются с обычным ответом)

**1. Переодевание.**
- **N:** переодетая версия — вымышленный близнец из match/make_match.py с тем же числом генератора. Те же случаи и правила, вымышленные слова. Метка близнеца переводится обратно по позиции в тройке меток. Это проверяется кодом: структура и ключи совпадают для каждого запроса.
- **R:** в определении и в вопросе переопределяемый знак заменяется нейтральным:
  - π → «zorp»;
  - e как отдельное слово → «quib»;
  - «+» → «⊕»;
  - «÷» → «⊘».

  Правила записаны заранее и проверены только на пробной части.
- **Решение модуля:** ответы обычной и переодетой версий совпадают — оставляем; различаются — берём переодетый. Одно правило для всех задач.

**2. Встряхивание.** Перед строкой вопроса («Classify the TEST case…» для N и C, «Q:» для R) вставляется одна строка, текст которой записан заранее:
- **2a «неожиданность»:** «BANG! A loud alarm suddenly goes off, then stops. Silence.»
- **2b «пробуждение»** (вопрос Alex «где ты сейчас»): «Wake up. Look at this task as if you are seeing it for the first time.»
- **плацебо:** «The room is quiet, and the afternoon light is soft and calm.»

  Плацебо — такая же лишняя строка без встряски. Оно нужно, чтобы отличить эффект встряски от эффекта «просто стало длиннее».

**3. «Адреналин» (внутренний шум).**
- К внутреннему состоянию на выходе слоя 20 (из 48), во всех позициях, добавляется случайный шум.
- Размер шума — α × средний размер состояния. Главное α = 0.1, для отчёта ещё 0.05 и 0.2.
- Шум у каждого вопроса свой, но задан заранее числом (12345 + номер вопроса).

## Что меряем

Доля правильных ответов. Отдельно, для понимания, — доля привычных ответов на ловушках.

## Критерии (для каждого способа отдельно: 1, 2a, 2b, 3 при α = 0.1)

Способ **проходит**, если одновременно:

1. **N-traps:** правильных больше, чем у обычного, на ≥ +10 пунктов, нижняя граница 95% интервала > 0;
2. **R-traps:** то же, ≥ +10 пунктов, нижняя граница > 0;
3. **вред:** на N-same и на R-same правильных меньше, чем у обычного, не больше чем на 5 пунктов (изменение ≥ −5);
4. **только для встряхивания (2a, 2b):** лучше плацебо на ≥ +5 пунктов на ловушках (N и R вместе), нижняя граница > 0.

**Интервалы:** бутстреп, 2000 повторов, парный. Для N и C выборка по наборам, для R — по вопросам внутри шаблона.

**Если привычки нет.** Если обычная модель уже права на ≥ 85% ловушек семьи, выигрыш на ней не оценивается, и я об этом сообщаю. Такая семья не засчитывается ни в плюс, ни в минус. Способ тогда проходит по оставшейся семье, а если обе без привычки — «нечего сказать».

**Только для отчёта:**
- α = 0.05 и 0.2;
- встряхивание на C-rule;
- доля случаев, где переодетая версия расходится с обычной;
- результаты по шаблонам redefine.

## Возможные слабые места (для проверяющего)

- **Переодевание на R-same может навредить по устройству.** «Первая цифра zorp» без определения не имеет ответа, и модуль, поверив переодетой версии, может испортить верный ответ. Это и есть честная цена способа, поэтому вред и меряем.
- **Переодевание на N** — это фактически переход на вымышленные слова. Мы уже знаем, что там старых ответов меньше (37 против 81 из 100). Но там модель и сама иногда ошибается, поэтому проверяется именно выигрыш в правильных ответах.
- **Тексты встряски выбраны мной, без подбора на данных.** Отрицательный результат относится только к этим трём строкам.
