# Сделать новое правило громче (14B, 2026-10-17)
Зеркало формулы Alex: с вопроса и дальше к весу внимания на строку «IMPORTANT UPDATE …» добавляется log(k). Варианты: в 40 копировщицах (b40), во всех головах слоёв 29–47 (late), 14–28 (mid) или во всех слоях (all). Плюс вариант без вмешательства: та же строка повторена прямо перед вопросом (_rep). Те же 240 запросов из sets_eras.json (наборы 15–29) + 120 с повтором.
Файлы: modal_boost.py, boost_Qwen2.5-14B-Instruct.jsonl, score_boost.py → score_boost_out.txt. Стоимость ≈ $1.
Проверки: k = 1 даёт в точности обычную модель (разница 0.000 на 300 запросах); границы строки напечатаны в первой строке jsonl; обычный режим и w0.1 совпадают с прошлым прогоном eras.

## Что это значит
1. Новое правило надо «услышать» в средних слоях (14–28), где модель выводит правило из примеров. Усиление в поздних слоях и в копировщицах не даёт ничего: там уже поздно.
2. Громче новое помогает там, где формула «тише старое» бессильна (нет свежего примера): 7–10% → 23–37%. А где свежий пример есть, лучше работает «тише старое» (90%), а слишком громкое новое (×16) мешает (60%).
3. Простой повтор строки перед вопросом сам по себе ничего не даёт (10% → 10%), только в паре с вмешательством.
4. Потолок пока около трети верных на трудных ловушках: привычку удаётся сломать (старых 90% → 37%), но правильный ответ появляется не всегда.
5. Вред: вмешательство касается только строки об изменении, поэтому там, где изменения нет, оно ничего не делает по построению. MMLU и GSM8K с ним не проверены.

## Дополнение: есть ли у модели правильный ответ (по сохранённым ответам, без новых запусков)
- Только новое правило, без истории («fresh», match/results): D1+D3 верно 26/30. Решать эти случаи модель умеет.
- Старое правило + строка об изменении, без примеров («change_0»): 13/30. Поправка «было — стало» сбивает её и без привычки. Это потолок, к которому может подвести тормоз.
- В обычном режиме правильный ответ — второй по силе в 22/30 ловушек (A60).
- Наши вмешательства дают 30–37% при потолке около 43%: эффект привычки от примеров снят почти полностью; остаток — слабость в применении поправки к правилу.
- Оговорка про подгонку: одна задача, одна модель; силу вмешательства выбирали после просмотра нескольких вариантов. Для проверки общности: заранее зафиксировать ×4 и прогнать на другом типе задач и другой модели.
