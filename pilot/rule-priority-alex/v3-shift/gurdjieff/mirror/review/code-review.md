## BLOCKERS
1. **score_mirror.py:156-163 TEMPLATE ranks items against their own label.** The per-item leave-one-out value is `(sum_y - y_i)/(n-1)`, so inside a cell every y=0 item ranks above every y=1 item. The cut falls inside a cell (R K=308: T6 115 + T0 50 + T5 120 + 23 more). On the real data TEMPLATE therefore covers T5 y=0 73/73 but T5 y=1 only 29/47. It covers C5 y=0 41/74 and C5 y=1 0/46. The D boundary cells (spider, triangle) behave the same way. This weakens the baseline in a way that depends on the label, which favours an M2 PASS. **Fix:** rank whole cells. Set `key = cell flip rate` (the same value for every item in a cell; either the full rate or a rate from out-of-fold cells). Fill whole cells in descending order. In the boundary cell, give each item the weight `remaining/n_cell`, the same expected-value treatment as RANDOM-S. `acc_i` already accepts fractional weights.
2. **The lamp is not frozen on record.** PLAN v2 says lamp_scores.json is frozen with its sha256 before the GPU pass, but no sha is written anywhere (../PREREG.md lists only the sensor files). **Fix:** before launching, append these sha256 values to PLAN.md (or mirror/PREREG.md): lamp_scores.json `37b19411…9f35804`, lines.json, mirror_g.py, and score_mirror.py (after fix 1).
